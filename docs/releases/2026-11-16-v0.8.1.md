# v0.8.1 Color-Safe Post-Processing

- Release date: 2026-11-16
- Tag: `v0.8.1`
- Milestone: v0.8.1 Color-Safe Post-Processing
- Branch flow: fix PR `bugfix/203-post-processing-washout` -> `develop`, then `release/v0.8.1` -> `main`, then backmerge to `develop`

## Summary

The v0.8.1 release restores visible bloom and vignette without washing out the
Android 2D scene. URP camera post-processing remains disabled because its
color-grading path corrupts the image on Android GLES. The release ships a
first-party full-screen feature that samples the camera color and applies a
threshold bloom and a subtle vignette with no color-grading LUT. The HUD and
touch controls stay on the native overlay path. Gameplay, balance, save data,
and persistent progression are unchanged.

## Included

- `JabaSurvivol/NeonPost` shader with an eight-tap threshold bloom and a
  vignette.
- `JabaNeonPostFeature` renderer feature at
  `BeforeRenderingPostProcessing` with the `NeonPost` material.
- `ProjectSetup.Configure` installs the material and renderer feature and
  enables the compatibility-mode define required by the 2D pass.
- Quality fallback for devices with two or fewer cores or less than 1536 MB of
  system memory.
- EditMode coverage for the shader, material, and renderer feature, and PlayMode
  coverage for the fallback and camera post-processing state.
- Android emulator evidence in English and Spanish for phone and tablet.

## Known issues and deferred work

- URP compatibility mode is deprecated upstream. It is isolated to the
  color-safe pass and must be removed when URP exposes a public 2D Render Graph
  color texture hook.
- Android evidence is emulator-only. Physical phone and tablet profiling
  remains in #99.
- No human playtest is claimed.
- Procedural audio remains placeholder audio; final authored audio remains in
  v1.0.0.
- The production APK is ARM64-only and is not installed on the x86_64
  emulator.
