# v0.5.1 Local Beta Security Checklist

- Status: Active, pre-beta gate open
- Issue: #108
- Related: #103, #101, ADR-0006, ADR-0007
- Evidence: `docs/playtests/evidence/v051-security-*`

## Scope

This checklist covers the private, Tailscale-only five-person beta. It reviews
network exposure, secret handling, log and evidence redaction, tester data
handling, and dependency security before testers connect.

Out of scope: public deployment, Oracle, VPS, paid infrastructure, full
penetration testing, payments, and architecture changes.

## Threat model

- The repository is public, but the beta runs on a private Tailscale network.
- Testers are five known people, not the public.
- Assets: beta accounts, refresh sessions, cloud saves, leaderboard entries,
  telemetry choices, remote config, and the development machine.
- Trust boundary: only the BFF is reachable by testers. PostgreSQL, Identity,
  Game, Telemetry, the Aspire dashboard, and OTLP remain on loopback.
- A default Tailscale access control list is allow-all, so the tailnet must be
  restricted before testers are invited.

## Network exposure

| Service | Beta bind | Port | Consumer | Reachable by testers |
|---|---|---|---|---|
| BFF | `127.0.0.1` behind `tailscale serve` (HTTPS) | 5247 | Five testers | Yes, over the tailnet only |
| Identity.Api | `127.0.0.1` | 5095 | BFF only | No |
| Game.Api | `127.0.0.1` | 5250 | BFF only | No |
| Telemetry.Worker | `127.0.0.1` | assigned at run time | none | No |
| PostgreSQL | `127.0.0.1` | assigned at run time | backend only | No |
| Aspire dashboard | `127.0.0.1` | 15184 | operator only | No |
| OTLP | `127.0.0.1` | 19183 | operator only | No |
| HTTPS dev profiles | `127.0.0.1` | 7228, 7299, 7251 | operator only | No |

Rules:

- Never bind any beta service to `0.0.0.0` or `::`.
- Every local container publish must use `127.0.0.1:host:container`. Do not use
  `-p host:container` without a host address.
- Expose only the BFF, and only through `tailscale serve` over HTTPS.
- The Unity client rejects cleartext HTTP for non-loopback hosts, so the BFF
  must be reached over HTTPS through `tailscale serve` or a TLS binding.
- Do not enable a router port forward, UPnP, or a public reverse proxy.
- Do not use `tailscale funnel`; it exposes a service to the public Internet.

## Tailscale controls

- Use tag-based, deny-by-default access control lists: `tag:beta-testers` may
  reach `tag:beta-host` on the BFF port only.
- Disable Tailscale SSH on the beta host unless a reviewed need exists.
- Disable exit-node advertisement and do not route tester traffic through the
  beta host.
- Confirm `tailscale funnel status` reports nothing enabled.
- Require device approval and key expiry for tester devices.
- Record `tailscale status`, `tailscale serve status`, and
  `tailscale funnel status` before testers connect.

## Verification results

- Identity.Api and Game.Api bound to `127.0.0.1` and were not reachable on the
  LAN address `192.168.3.8`.
- A manual PostgreSQL container published with `-p 5433:5432` was reachable on
  the LAN. The corrected `-p 127.0.0.1:5433:5432` was reachable only on
  loopback. Recorded as finding F1.
- No beta service was bound to `0.0.0.0` in the reviewed configuration.
- Public-Internet reachability: the development machine has no configured
  router port forward and no service binds a public interface. A live external
  probe from a non-tailnet network is a pre-beta gate in #101 and must be
  recorded before testers connect.

Evidence: `v051-security-port-bind-audit.txt`.

## Secrets

- `Jwt__SigningKey` and `ConnectionStrings__Database` come from environment
  variables or a local secret store, never from committed configuration.
- The AppHost generates a new signing key per run, which invalidates sessions on
  restart. The beta host must provide a stable signing key through the
  environment for the beta window.
- `.env` files are ignored; `.env.example` holds local defaults only.
- `deploy/secrets` stores SOPS-encrypted secrets only.
- Keystores, private keys, and tokens are never committed.
- Secrets never appear in logs, screenshots, or evidence.

Verification result: no tracked keystore or private key, no hardcoded signing
key, and only the secrets README tracked under `deploy/secrets`.

Evidence: `v051-security-secret-scan.txt`.

## Logs and evidence

- Access tokens, refresh tokens, passwords, save documents, and personal data
  are never logged.
- Evidence is redacted before it is committed.
- Only synthetic test-account values appear in committed evidence.
- Server logs are sampled before testers connect.

Verification result: no token, password, signing key, or connection string was
found in the reviewed evidence or in the sampled Identity and Game server logs.
Entity Framework SQL logging is Development-only.

Evidence: `v051-security-evidence-review.txt`,
`v051-security-server-log-review.txt`.

## Tester data

- Testers consent to the data described in the beta plan.
- Telemetry is opt-in and defaults to off; opted-out clients send nothing.
- Raw telemetry events are retained for 30 days by the telemetry worker.
- Raw feedback and tester identities stay in the private beta channel.
- A tester may request deletion of their account, saves, leaderboard entries,
  and telemetry events.

Deletion procedure: one transaction removes telemetry events, the affected
daily aggregates, leaderboard runs, cloud saves, refresh sessions, and the
account. Manual backups, logs, and traces are deleted when the beta ends or on
request.

Verification result: the procedure was exercised with a test account. Before
deletion the account had one refresh session, one cloud save, and one
leaderboard run; after deletion all counts were zero and login returned `401`.

Evidence: `v051-security-deletion-exercise.txt`.

## Dependencies and containers

- Dependency audit: no vulnerable package after upgrading the AppHost SDK to
  `Aspire.AppHost.Sdk/13.6.5`. The CI dependency audit is advisory; the manual
  audit is the authoritative result.
- Container CI builds all four images and scans them with Trivy for critical
  and high findings.
- The security workflow runs CodeQL and the dependency audit.

Evidence: `v051-security-dependency-audit.txt`.

## Accepted residual risks

- Leaderboard submissions and cloud saves trust client-reported progression
  with shape and bounds validation. ADR-0006 documents this limitation for the
  trusted five-person beta. Server-side run simulation is a later anti-cheat
  step.
- The BFF trusts forwarded headers from the local proxy. For the local beta the
  BFF is reachable only through `tailscale serve` on the beta host; a broader
  deployment must restrict forwarded headers to the real proxy.
- The Aspire dashboard and OTLP endpoint are loopback-only and are not exposed
  to testers.
