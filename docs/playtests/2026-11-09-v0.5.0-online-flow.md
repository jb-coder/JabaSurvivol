# v0.5.0 Online Flow Verification

- Date: 2026-11-09
- Version under test: `0.5.0` (version code `5`)
- Backend: PostgreSQL, Identity.Api, Game.Api, Telemetry.Worker, and BFF
- Local orchestration: Aspire AppHost (`src/AppHost`) plus fixed-port services for
  scripted API verification
- Android: API 35 x86_64 emulator, phone 1080x2340 @ 440 dpi and tablet
  2560x1600 @ 320 dpi

## Automated backend flow

`tools/e2e/Verify-OnlineFlow.ps1` ran against the BFF and produced
`docs/playtests/evidence/v05-online-flow.json`:

| Step | Result |
|---|---|
| Register a new account | `201` |
| Login | `200` |
| Refresh access token | `200` |
| Current account (`/me`) | `200` |
| First cloud save (`baseRevision: 0`) | `200`, revision assigned |
| Read cloud save | `200` |
| Stale save revision | `409` with current revision |
| Update with current revision | `200` |
| Leaderboard submission | `200`, idempotent duplicate `200` |
| Public leaderboard contains the account | `true` |
| Telemetry batch | `200`, 2 accepted |
| Duplicate telemetry batch | `200`, 2 duplicates |
| Remote config | `200` |
| Telemetry daily aggregate | `RunCount=1, KillCount=0, EventCount=2` |
| Logout | `204` |
| Refresh after logout | `401` |

Remote-config toggles were exercised without an APK rebuild:

- `v05-remote-config-disabled.json` shows cloud saves, leaderboards, and
  telemetry disabled.
- `v05-remote-config-enabled.json` shows all three enabled with a sample rate
  of `1`.

The AppHost startup log is in `v05-apphost-start.txt`; it launched PostgreSQL
and the four workloads. Fixed-port services were used for the API script so the
evidence is deterministic.

## Acceptance mapping

- Local backend with PostgreSQL and all services: AppHost started; scripted API
  flow passed against PostgreSQL-backed services.
- Android 0.5.0 emulator APK installed: badging and install recorded.
- Register, login, refresh, sign out: API flow passed; UI account evidence
  covers signed-out, signed-in, and offline states.
- Cloud backup and restore: API and Android conflict/keep-local/use-cloud
  evidence passed.
- Stale revision conflict with both choices: `409` verified; Android conflict
  dialog and both choices captured.
- Completed run on the leaderboard: submission and public query verified;
  leaderboard panel evidence captured.
- Opt-in telemetry and daily aggregate: batch, duplicate, aggregate, and opt-in
  toggle verified; opted-out clients send nothing by design and PlayMode tests.
- Remote config without APK rebuild: disabled/enabled JSON captured.
- Phone and tablet layouts without crashes: account and cloud panels captured
  on both layouts; no app fatal exceptions in logcat.

## Residual limitations

- The final emulator UI capture was blocked by a system-level ANR after repeated
  rebuilds. The UI evidence is from the same feature code and the final APK
  packaging is verified separately.
- Automated verification only; no human playtest was performed.
- Deployment to Oracle staging remains blocked by #81.
