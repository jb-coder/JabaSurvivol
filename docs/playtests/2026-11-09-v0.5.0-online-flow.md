# v0.5.0 Online Flow Verification

- Date: 2026-11-09
- Version under test: `0.5.0` (version code `5`)
- Backend: PostgreSQL, Identity.Api, Game.Api, Telemetry.Worker, and BFF
- Verification stack: fixed-port local services backed by PostgreSQL
- Android: API 35 x86_64 emulator, phone 1080x2340 @ 440 dpi and tablet
  2560x1600 @ 320 dpi

## Automated backend flow

`tools/e2e/Verify-OnlineFlow.ps1` asserts every status and fails on mismatch.
It produced `docs/playtests/evidence/v05-online-flow.json`:

| Step | Result |
|---|---|
| Register a new account | `201` |
| Login | `200` |
| Refresh access token | `200` |
| Current account (`/me`) | `200` |
| First cloud save (`baseRevision: 0`) | `200`, revision assigned |
| Read cloud save and compare document | `200`, supplies match |
| Stale save revision | `409` with current revision |
| Update with current revision | `200` |
| Leaderboard submission | `200`, idempotent duplicate `200` |
| Public leaderboard contains the account | `true` |
| Telemetry batch | `200`, 2 accepted |
| Duplicate telemetry batch | `200`, 2 duplicates |
| Remote config | `200` |
| Telemetry daily aggregate | `RunCount=2, KillCount=0, EventCount=4` |
| Logout | `204` |
| Refresh after logout | `401` |

Remote-config toggles were exercised without rebuilding the APK:

- `v05-remote-config-disabled.json` shows cloud saves, leaderboards, and
  telemetry disabled.
- `v05-remote-config-enabled.json` shows all three enabled with sample rate `1`.
- Both snapshots were captured from the same BFF and Game.Api images after
  restarting only the backend configuration.

The `src/AppHost` project started successfully, but the scripted flow above used
fixed-port services so the API evidence is deterministic. A full Aspire resource
list was not captured.

## Android packaging

`v05-e2e-apk-badging.txt` is the full `aapt dump badging` output:

```text
package: com.jabasurvivol.game versionCode=5 versionName=0.5.0
sdkVersion: 26
targetSdkVersion: 36
native-code: arm64-v8a x86_64
uses-permission: android.permission.INTERNET
```

`v05-e2e-apk-install.txt` records the successful install and the package
version. `v05-e2e-apk-launch.txt` records the launch command. The app process
started, but the emulator reached a system-level ANR before the 0.5.0 menu
rendered, so a complete 0.5.0 UI flow was not captured. `v05-e2e-android-logcat.txt`
contains the actual Unity startup log for that attempt and no app fatal,
unhandled, or null-reference exception.

The UI screenshots from the earlier feature slices are not re-labelled as 0.5.0
evidence. They remain available for account, cloud, leaderboard, and telemetry
UI verification, but their own smoke records state the app version at capture
time.

## Blocking limitation

The final 0.5.0 emulator run did not complete the phone/tablet UI flow because
the emulator entered a system-level ANR after repeated rebuilds. The blocking
action is to rerun the 0.5.0 APK on a healthy emulator or a physical device and
capture the account, cloud, leaderboard, telemetry, and conflict screens. Issue
#82 remains open and blocked until that evidence exists.

Automated verification only; no human playtest was performed. Deployment to
Oracle staging remains blocked by #81.
